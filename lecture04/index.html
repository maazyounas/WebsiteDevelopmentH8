Web Development - Lecture 04

Git, GitHub & Introduction to CSS

1. Introduction

In this lecture, we learned the basics of Git and GitHub, installed Git on our computers, connected GitHub with VS Code, and learned the basic commands used to manage and share our projects.

2. What is Git?

Git is a version control system used to track changes in source code and project files.

Git allows developers to save different versions of their projects and keep track of changes over time.

Why do we use Git?

  • Track changes in a project
  • Save different versions of code
  • Undo changes when necessary
  • Work with other developers
  • Manage projects efficiently
  • Connect local projects with GitHub

3. What is GitHub?

GitHub is a platform where developers can store, manage, share, and collaborate on software projects using Git.

Git is the version control system, while GitHub is an online platform that can host Git repositories.

Git vs GitHub

Git GitHub
Version control system Online platform for Git repositories
Runs on your computer Runs primarily as an online service
Tracks project changes Stores and shares repositories online

4. Installing Git

Before using Git commands, Git needs to be installed on the computer.

Basic Steps

  1. Download Git for your operating system.
  2. Run the Git installer.
  3. Follow the installation steps.
  4. Complete the installation.
  5. Open Terminal or Git Bash.
  6. Check whether Git is installed.

Check Git Installation

```

git --version
```

If Git is installed correctly, the terminal will display the installed Git version.

5. Creating a GitHub Account

GitHub requires an account to create and manage repositories online.

Basic Steps

  1. Open the GitHub website.
  2. Click Sign Up.
  3. Create or use an email account.
  4. In our setup, we used the Continue with Google option to create/sign in to the GitHub account.
  5. Complete the required account setup.

6. Connecting VS Code with GitHub

Visual Studio Code provides Git and GitHub integration, allowing developers to work with repositories directly from the editor.

We signed into GitHub from VS Code so that our local development environment could work with our GitHub account.

Why connect VS Code with GitHub?

  • Clone repositories
  • Publish projects
  • Commit changes
  • Push changes
  • Pull changes
  • Manage source control

7. Useful VS Code Extensions

VS Code extensions can make development and Git workflows easier.

Common Extensions / Tools

  • Live Server - Runs HTML webpages locally.
  • Prettier - Formats code.
  • Auto Rename Tag - Helps rename HTML tags.
  • Auto Close Tag - Automatically adds closing tags.
  • GitHub integration - Helps work with GitHub repositories from VS Code.

8. Configuring Git

Before making commits, we configure Git with our name and email address.

Configure Username

```

git config --global user.name "Your Name"
```

Configure Email

```

git config --global user.email "[your-email@example.com](mailto:your-email@example.com)"
```

Replace the example values with your own name and email address.

Check Git Configuration

```

git config --global user.name

git config --global user.email
```

These settings tell Git who is making the commits on the computer.

9. What is a Repository?

A repository, commonly called a repo, is a project managed by Git.

A repository can contain source code, images, documentation, configuration files, and other project files.

A repository can exist locally on your computer and can also be hosted on GitHub.

10. Creating a Git Repository

To start tracking a local project with Git, we can initialize a Git repository. 

```

git init
```

This creates a hidden .git directory that stores information used by Git.

11. Checking Git Status

The git status command shows the current state of the Git repository. 

```

git status
```

It can show files that have been modified, added, or are not yet being tracked.

12. Git Add

The git add command adds changes to the staging area.

Add one file:

```

git add index.html
```

Add all changed files:

```

git add .
```

The staging area allows us to choose which changes will be included in the next commit.

13. Git Commit

A commit saves a snapshot of the staged changes in the local Git repository. 

```

git commit -m "Initial commit"
```

The message describes what was changed in that commit.

14. Git Log

The git log command displays the commit history of the repository. 

```

git log
```

It can show information such as commit ID, author, date, and commit message.

15. Git Branch

A branch is a separate line of development in a Git repository.

Check current branch:

```

git branch
```

Create a new branch:

```

git branch feature
```

Switch to a branch:

```

git switch feature
```

Branches are useful when developers want to work on different features without directly changing the main branch.

16. What is a Remote Repository?

A remote repository is a version of a Git repository stored somewhere other than your local computer.

GitHub is commonly used to host remote Git repositories.

Add a GitHub repository as a remote:

```

git remote add origin https://github.com/username/repository.git
```

Check remote:

```

git remote -v
```

17. Git Push

The git push command sends local commits to a remote repository such as GitHub. 

```

git push
```

A common first push can be: 

```

git push -u origin main
```

After the upstream branch is configured, future pushes can often be performed using: 

```

git push
```

18. Git Clone

The git clone command creates a local copy of a remote Git repository. 

```

git clone https://github.com/username/repository.git
```

This is useful when you want to download an existing project from GitHub and work on it locally.

19. Git Pull

The git pull command gets changes from a remote repository and integrates them into the current local branch. 

```

git pull
```

It is commonly used when other developers have pushed new changes to the remote repository.

20. Git Fetch

The git fetch command downloads information about changes from a remote repository without automatically integrating those changes into your current branch. 

```

git fetch
```

21. Git Diff

The git diff command shows differences between versions or changes in files. 

```

git diff
```

22. Basic Git Workflow

A common workflow for updating a project is:

  1. Make changes to your project.
  2. Check the changes.
  3. Add the changes to staging.
  4. Create a commit.
  5. Push the commit to GitHub.
```

git status

git add .

git commit -m "Updated project"

git push
```

23. Working with an Existing GitHub Project

When you want to work on an existing GitHub project, you can clone it. 

```

git clone https://github.com/username/repository.git
```

Then enter the project directory: 

```

cd repository
```

After making changes: 

```

git add .

git commit -m "Updated project"

git push
```

25. Creating a GitHub Repository

A GitHub repository is an online location where a project can be stored and shared.

Basic Steps

  1. Sign in to GitHub.
  2. Create a new repository.
  3. Give the repository a name.
  4. Choose whether it should be public or private.
  5. Create the repository.
  6. Connect the local Git repository to GitHub.
  7. Push the project to GitHub.

26. Local Repository vs Remote Repository

Local Repository Remote Repository
Stored on your computer Stored on a remote service such as GitHub
Managed using Git Can be accessed through the internet
Used for local development Used for sharing and collaboration
